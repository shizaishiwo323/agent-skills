# 论文逐段逻辑梳理

目标:读完梳理后,读者能知道原文每一段说了什么、按什么顺序说、这一段在全文中起什么作用。这不是摘要。摘要会丢掉段落层级和细节,而用户需要的是按顺序展开的骨架,同时保留完整信息量。所以宁可长,也不要压缩。

完整交付分三部分,按顺序进行:

1. **逐段梳理**(主体)。
2. **全文骨架**:把第 1 部分里每段的"概括"和"作用"原样抽出来,按章节结构排好。
3. **询问图表梳理**:问用户是否需要把全文图片和表格单独梳理;用户同意后才做。

## 梳理模式

动笔前先看用户有没有限定范围。没有限定就按完整模式。

| 模式 | 用户怎么说(示例) | 输出 | 结尾 |
|---|---|---|---|
| 完整(默认) | 没有限定;"梳理这篇论文" | 逐段梳理 → 全文逻辑主线 → 全文骨架 | 询问是否梳理图表 |
| 只梳理骨架 | "只梳理骨架""只要骨架""只出骨架" | 全文骨架(可加一句全文逻辑主线) | 询问是否梳理图表 |
| 只梳理图表 | "只梳理图片""只梳理图表""只要图和表" | 图表梳理的 MD 文档 | 不再询问 |

- 用户限定了哪部分,就只输出哪部分,不要顺带输出别的部分,也不要先问"要不要也做全文梳理"。
- 用户同时点名两部分(如"骨架和图表"),就两部分都做,不再询问。
- "只梳理图片"也包括表格;用户明确说"只要图片、不要表格"时才去掉表格。
- **只梳理骨架**:仍要按"工作流程"第 1 步通读全文、列段落清单,逐段想清楚"概括"和"作用",写法要求与完整模式相同(独立成句、第 n/N 段编号、信息量底线中与这两句有关的数值和图号照样保留)。只是不输出段内逻辑链要点,直接按"全文骨架"的格式输出。
- **只梳理图表**:跳过逐段梳理和骨架,直接执行"图表梳理"一节(含环境检查)。每项的"正文引用"仍按"3.2 第 2/4 段"的写法定位,所以要先列出段落清单,确定每段的 n/N。这个模式下图表**按论证逻辑排序**,并且每张图都要讲清"现象 → 作者推测的机理",见"图表梳理"中的"排序"和"只梳理图表模式的额外要求"。

## 工作流程

1. **先通读全文再动笔。** 读完摘要、所有章节、结论和附录,确定章节编号、小节划分和每一节的自然段数。先列出这份"段落清单"再写,这样后面的章节不会因为篇幅长而省掉段落层级,每段的"第 n/N 段"编号也能一开始就定准。
2. **检查 PDF 里的批注**(高亮、彩色下划线、"创新点"等标注)。有的话记下位置,写到对应段落后面。
3. **逐章逐节逐段写。** 按下面的格式要求输出。
4. **写全文逻辑主线和全文骨架**(见"结尾")。
5. **输出前自查**(见文末清单)。
6. **询问图表梳理**(见"图表梳理")。

以上是完整模式的流程;限定模式按"梳理模式"一节删减。
7. **逐段梳理和骨架直接在对话里输出,不要生成文件。** 这是用户明确要求的。论文很长时,分多条回复接着写,每条结束处注明"接下来梳理第 X 章",用户说"继续"就接着写,不要中途压缩或跳过。骨架放在最后一条;那一条放不下时,单独再发一条。只有图表梳理需要生成文件,因为图片要从原文件截出来才能显示。

## 范围

- 要梳理:摘要、正文所有章节、结论、附录(附录同样逐段)。
- 不梳理:致谢、参考文献。
- 段落划分以原文版面的自然段为准。排版不清、拿不准时按语义判断,并在该处用"(注:……)"简短说明。

## 结构与标题

1. 层级:章 → 节(小节)→ 段。每一章、每一个小节都拆到"段"这一级。
2. 章、节标题写成"原文编号 + 英文原标题 + 中文译名",例如:`2.2 SIP and EDL polarization 与 EDL 极化`。
3. 标题后用括号标注原文段落数,例如"(共 3 段)"。章标题和第一个小节之间如果有引导段,单独列为"引导段(共 1 段)"。
4. 每段小标题写成"第 n/N 段:一句话概括本段主题"。n 是本段序号,N 是当前这一组的总段数,与标题里的"(共 N 段)"一致。例如 2.2 节共 3 段,就依次写"第 1/3 段""第 2/3 段""第 3/3 段"。
   - "一组"指段落直接所属的最小单位:有小节时是小节;没有小节的章是整章;引导段、摘要、附录各自单独成组。
   - 每进入新的一组,n 从 1 重新计数。
   - 这一句概括会被原样抄进"全文骨架",所以要写成独立可读的一句话,不要依赖上下文(不要写"同上""接着说明"这类)。

## 每段怎么写

1. 用若干条短要点,按原文句子先后顺序写出这一段的逻辑链。一般原文一两句话对应一条要点。
2. 每条要点写"这句话说了什么 + 它在段内起什么作用"。可用的连接词:起始句/主旨句点明……;以……为例,引出……;按前文顺序分别……;进一步地……;为后文……铺垫;结论句……;与已有工作对比……
3. 每段最后单独一行写"作用:……",说明这一段在全文中的功能,如建立背景、提出问题、点明研究空白、给出依据、设置对照、证明优势、划定边界、展望。这一行同样会原样进入骨架,写成一句完整的话。
4. 摘要也按段梳理,用编号写逻辑:背景问题 → 方法 → 验证 → 额外发现 → 意义。

写法示范见 `references/examples.md`,动笔前读一遍。示例只用来学习粒度和语气,不要照搬内容。

## 信息量底线(不能丢)

这些内容丢了,梳理就失去了价值,因为读者会回头再去翻原文核对。

1. **保留关键信息**:公式编号(式 n)、图表编号(Fig. n / Table n)、参数值和单位、样品参数、仪器型号、频率范围、噪声水平、反演结果数值、被引文献(作者 + 年份)。
2. **公式**写出核心关系即可(如 T₂ = r/(αρₛ)),不必抄完整推导。推导类段落要写清"从哪一步到哪一步、关键一步是什么"。
3. **假设、适用条件、失效情形、作者自己承认的局限**,单独成条写出,不能被概括掉。
4. **只梳理原文内容,不添加原文没有的观点。** 需要补充时用"(注:……)"标出,与原文内容区分开。

## 文风

- 中文,句子短,一句只说一件事。
- 术语首次出现时附英文或缩写,如 双电层(EDL)。
- 不写成大段文字,也不要过度加粗。

## 开头与结尾

- **开头**:论文中文标题、作者、年份、期刊,再加一行体例说明:"每一章先标段落数,再逐段写'核心内容 → 作用';第 n/N 段表示本节共 N 段中的第 n 段"。
- **批注**:PDF 中有用户批注时,在对应段落后用"📌"注明批注位置和原文对应内容。
- **结尾**,依次写两块:
  1. **全文逻辑主线(一句话串联)**:用 → 把全文从背景、问题、方法、验证、应用到局限和展望串成一条线。
  2. **全文骨架**:规则见下一节。
- 骨架之后,用一句话询问图表梳理(见"图表梳理")。

## 全文骨架

骨架让读者一屏看清全文的结构和每段的分工。它不产生新内容,只是把前面写好的东西重新排一遍。

1. **最小单位是段落,每段只有两句话**:
   - 概括:该段小标题"第 n/N 段:"后面的那句话。
   - 作用:该段末尾"作用:"那一行。
   两句都**原样复制**,不改写、不缩写、不合并。段内的逻辑链要点不进骨架。
2. **外层是章节结构**:章 → 节 → 段,标题与段落数沿用正文梳理里的写法(原文编号 + 英文原标题 + 中文译名 +(共 N 段))。摘要、引导段、附录照常列出。
3. **一段不漏**:骨架里的段落数必须与正文梳理逐组一致。
4. 格式(Markdown,章用三级标题,节用四级标题,段用列表):

```markdown
## 全文骨架

### 摘要(共 1 段)
- 第 1/1 段:……
  - 作用:……

### 1 Introduction 引言(共 4 段)
- 第 1/4 段:……
  - 作用:……
- 第 2/4 段:……
  - 作用:……

### 2 Theory 理论
#### 引导段(共 1 段)
- 第 1/1 段:……
  - 作用:……
#### 2.1 NMR relaxation NMR 弛豫(共 3 段)
- 第 1/3 段:……
  - 作用:……
```

## 图表梳理(询问后才做)

全部梳理和骨架输出完后,在最后一条回复的末尾问一句:

> 需要把全文的图片和表格单独梳理出来吗?图片会从原文件截取对应位置展示,表格整理成 Markdown 表格,汇总成一份 MD 文档。

用户没有同意就不做。同意后,或用户一开始就限定"只梳理图表",按下面执行。

### 范围

- 对象:论文全文(含附录)的所有图和表;用户另外上传的资料(补充材料、其他文档、单独的图片)里的图和表也一并处理。

### 排序

- **完整模式下询问后再做的图表梳理**:按原文编号顺序(Fig. 1, Fig. 2 … Table 1 …;补充材料的 Fig. S1 等排在正文之后)。
- **只梳理图表模式**:按讲解最通顺的逻辑顺序排,不按图号,也不按图在文中出现的位置。目标是让读者从头读到尾就能顺下来作者的论证。
  1. 动笔前先通读全文,理出作者的论证链,一般是:研究对象与装置 → 方法或模型怎么得到数据 → 直接观测到的现象 → 由现象提取的参数或定量关系 → 作者的机理解释 → 验证或对比 → 推广与局限。按这条链给每张图表定位。
  2. 表格、补充材料的图(Fig. S…)也插到它在论证中真正起作用的位置,不要统一堆到最后。只是重复或旁证、放进主线会打断讲解的,放到文末"补充图表"一节,并注明它支撑哪一步。
  3. 文档开头先给一张"讲解顺序表":讲解序号、图表编号、页码、这一步回答的问题(一句话)。再用一段话写出这条论证链。
  4. 每一项标题写成"第 k 步 · Fig. n 中文图题(第 p 页)",保留原文图号,方便回原文核对。

### 截取图片

图片必须来自用户上传的原文件,不能自己重画或用文字代替。按文件类型:

- **先检查环境**(PDF 和 Word 都要用到脚本,开始截图前做一次):
  1. 运行 `python -c "import fitz; print(fitz.version)"`(Windows 上 `python` 不可用时试 `py`,macOS/Linux 试 `python3`)。
  2. 报 `ModuleNotFoundError` 就运行 `python -m pip install pymupdf`,装好后再检查一次。
  3. 机器上没有 Python,或安装失败(无网络、权限不足),就停下来告诉用户原因和需要执行的命令,不要改用文字描述代替截图。
- **PDF**:运行本技能目录下的 `scripts/extract_figures.py`(用完整路径调用)。
  1. `python scripts/extract_figures.py scan 论文.pdf 输出目录/figures`:自动识别图注和表注,裁出每张图和表,生成 `manifest.json`(图号、页码、裁剪框、图注原文)。
  2. **逐张打开裁出的 PNG 核对。** 自动裁剪只是初稿。检查:图是否完整(panel、坐标轴、图例、色标都在),有没有混进正文,有没有漏图。标为 `fallback` 的项必须重点检查。
  3. 不准的,用 `page 论文.pdf 输出目录/pages --pages 页码 --grid` 渲染带 50pt 网格的整页,读出坐标,再用 `crop 论文.pdf 页码 x0 y0 x1 y1 输出目录/figures/Fig_3.png` 手动重裁。扫描版 PDF 没有文字层,自动识别会失败,直接用 page + crop。
- **Word(.docx)**:`python scripts/extract_figures.py docx 文档.docx 输出目录/figures` 导出嵌入图片,再对照正文确认每张对应的图号。
- **用户直接上传的图片**:原图复制到 `figures/`,按图号重命名。
- 一张图分成多页、或一个编号下有多张子图时,分别截取,按 `Fig_3a.png`、`Fig_3b.png` 命名。

### 表格

- 主体用 Markdown 表格**完整重建**:所有行列、数值、单位、符号、上下标、表注和脚注都保留,不做取舍、不四舍五入。
- 数值以原文为准,逐格核对。PDF 文字层提取的数字容易错位,要对照截图检查。
- 多级表头、合并单元格无法用 Markdown 如实表达时,把合并的值在每一行重复写出,并在表下用"(注:……)"说明;同时附上原表截图。

### 每一项写什么

```markdown
### Fig. 3 中文图题(第 7 页)

![Fig. 3](figures/Fig_3.png)

- 图注:图注的中文转述,保留符号、单位、panel 标记。
- 画了什么:按 panel (a)(b)… 逐个说明横纵轴、对象、对比组。
- 正文引用:在哪些段落被引用,沿用正文梳理里的位置写法,如"3.2 第 2/4 段""4.1 第 1/3 段",以及在那里用来说明什么。
- 支撑的结论:这张图在原文论证里用来证明什么。

### Table 2 中文表题(第 9 页)

| 列 1 | 列 2(单位) | … |
|---|---|---|
| … | … | … |

- 表注 / 脚注:……
- 正文引用:……
- 支撑的结论:……
```

与逐段梳理一样,只写原文内容;补充用"(注:……)"标出。

### 术语卡(两种模式都要)

写"画了什么"时,凡是这份图表梳理里第一次出现、读者可能不熟悉的模型、参数、符号、缩写和专业概念,就地加一张术语卡,不要留到文末,也不要默认读者已经知道。例如 Cole-Cole 模型、σ′ 和 σ″、τ、PV(孔隙体积)、ABMN 四电极、Bootstrap 不确定性、多晶型。

- 写法:
  - 是什么:一句话说明,附英文全称或缩写。
  - 公式:模型类术语写出核心公式,并说明每个符号。
  - 参数表:逐个写符号、单位、物理意义,以及这个参数变大或变小在本文的体系里意味着什么。
  - 本文怎么用:原文用这个量说明了什么,或者取值是多少。
- 每个术语只在第一次出现时写一次卡片。之后再出现时写"(见第 k 步 术语卡)"。
- 卡片里属于通用背景知识的内容(教科书定义、公式的一般形式)用"(注:……)"或"背景:"标出,和原文内容分开。原文给出的定义、取值和公式优先,并注明出处(式 n、第几段)。不确定的不要编;原文和通用写法不一致时,两种都写出来并说明差别。
- 格式示例见 `references/examples.md` 的示例 4。

### 只梳理图表模式的额外要求

在"每一项写什么"的基础上,每张图再加两条,放在"支撑的结论"之前:

- **现象 → 机理**:先写图上能直接看到的现象(哪个量随什么变、变了多少、在哪里出现拐点或分阶段),再写作者对此提出的机理解释,说清"作者用哪个现象推出哪一步机理"。作者自己说是推测、假设、"可能"(propose、suggest、may be attributed to 等)的,照原文的确定程度写成"作者推测……",不要写成定论;作者给了旁证的(其他图、文献、表征手段),写明是哪一个。
- **承上启下**:一两句话说明上一步留下了什么问题、这张图怎么回答,又引出下一步的什么问题。

全文最后加一节"机理总图",用文字(必要时配简单示意)把各步的现象和对应的机理串成一条因果链,标出哪些环节有直接证据、哪些只是作者推测。

### 交付

- 输出到一个文件夹:`<论文简称>_图表梳理.md` 加同级的 `figures/`。MD 里用相对路径引用图片,保证换个位置打开也能显示。
- 生成后,用当前环境能渲染 Markdown 的方式展示给用户(在文件面板打开,或作为文件发送),并告诉用户文件位置。
- 回复里简单列出共几张图、几张表,以及哪些图是手动修正过裁剪、哪些表附了截图。

## 输出前自查

逐段梳理:
- 每个章节是否都拆到了段落层级,段落数是否与原文一致?
- 每段小标题是否都是"第 n/N 段",N 是否与"(共 N 段)"一致,每组是否从 1 重新计数?
- 是否保留了原文的数值、公式编号、图号和引文?
- 每段是否都有"作用:"这一行?
- 附录是否也逐段梳理?
- 后半部分的章节,粒度是否和前半部分一致?(最容易出现的问题是越写越粗。)

全文骨架:
- 是否每段都在,且只有"概括 + 作用"两句?
- 两句是否与正文梳理里的原句逐字一致?
- 章节标题、段落数是否与正文梳理一致?

图表梳理(做了的话):
- 是否每个图号、表号都有?完整模式下是否按编号排序;只梳理图表模式下,是否按论证逻辑排序,开头是否有讲解顺序表和论证链?
- 第一次出现的模型、参数、符号、缩写是否都有术语卡,参数是否都写了单位和物理意义?
- 只梳理图表模式下,每张图是否都有"现象 → 机理"和"承上启下",推测是否保持了原文的确定程度,文末是否有机理总图?
- 每张截图是否都打开看过,完整且没有混入正文?
- 表格数值是否逐格核对过原文?
